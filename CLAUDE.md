# netsuite-agent: notes for Claude Code

An agent builder (`apps/agent-builder`, `pnpm builder`) that turns a NetSuite use case written in plain language into a Claude Managed Agent on Oracle's NetSuite AI Connector, with fixed safety rules; plus the SuiteCloud (SDF) project for account changes. Plan and results: `docs/agent-builder-plan.md` (Phases 1 to 3 done); using it: `docs/agent-builder.md`; operating it: `docs/runbook.md`. The MCP gateway that came first (checkpoints CP0 to CP5, all passed) was **retired 2026-10-31** (ADR 0007); its code is in git history under the tag `gateway-final`, and its docs (`docs/design.md`, `docs/cp*-evidence.md`, ADRs 0001 and 0003-0006) are history. New work only when the owner starts it.

## Start of every session

1. Run `node scripts/doctor.mjs` and read every FAIL and WARN. Verify, never assume: if a tool is missing, stop and tell the user what to install (doctor prints the fix); do not install system software (JDK, Homebrew packages, global npm CLIs) without asking.
2. `git status` and `git log --oneline -5` to see where work stopped.
3. Read "Current state" below, then continue at the first unchecked item in "Next work".

### Findings worth remembering

- SuiteQL quirk: `COUNT(*)` + table alias + `ORDER BY` fails; use `COUNT(t.id)`. No `GROUP BY BUILTIN.DF(...)`.
- Sales order status codes in SuiteQL are single letters (A pending approval, B pending fulfilment, D partially fulfilled, E pending billing/partially fulfilled, F pending billing, G billed, H closed).
- Terms and customer category lists are not queryable by the role.
- Mac toolchain: Node 26.7.0, pnpm 10.28.0, git, Temurin JDK 21, SuiteCloud CLI 4.1.1 (supported on Node 24; if `suitecloud` misbehaves on 26, run it under Node 24), `ant` 2.4.0, `gh`, Claude Code.
- Effective permissions of employee 2815 + NS Agent Integration include setup permissions not in the role XML (the employee's global permissions). They stay (owner decision 2026-10-30).
- Managed Agents: Anthropic may start a scheduled run up to 9 minutes late. Webhooks need a public HTTPS endpoint, so waiting runs are found by polling.

## Rules that are not negotiable

- **Never write to NetSuite outside an approved agent run.** NetSuite data changes happen only when a builder agent calls a write tool and the owner approves that exact request on the run page. Never call Oracle's write tools from Claude Code or a connector directly. Never weaken the builder's fixed rules (`src/rules.ts`, `src/catalog.ts`) without the owner's decision.
- **Account changes ship only as SDF objects in `netsuite/` via PR** and an approved `deploy-sdf` run (ADR 0002). No live configuration edits.
- **Demo account only.** The builder allows only TSTDRV1755417's connector URL; never configure 9173162.
- **No secrets in the repo or in output.** Never print tokens, the client secret or private keys; `ant auth status` output names the credential, so check its exit code only.
- OAuth consents and integration-record changes are the owner's clicks.
- Commits: small, imperative subject, one concern each. Open PRs for anything under `netsuite/src/Objects/` or `apps/agent-builder/src/rules.ts`.
